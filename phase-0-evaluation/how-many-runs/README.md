# How many runs are enough?

## Question

How many runs do we need before a difference in answer quality between two setups can be trusted?

## Hypothesis

Three runs are enough: more runs would barely change the conclusions. This is a pure gut feeling.

## Setup

### Idea

Run the same setup many times and measure how much the results differ when nothing has changed (an A/A comparison). Any difference between two groups of identical runs is noise, so a real difference between two setups has to be larger than that to be trusted.

### Fixed conditions

- **Harness:** the one from [retrieval-vs-generation-metrics](../retrieval-vs-generation-metrics/README.md), reused unchanged: same 150 HotpotQA questions (seed 42), same context builder (`contexts.py`), same generator prompt (`prompts.py`), same metric code (`shared/eval/`).
- **Conditions:** C1 (both gold paragraphs in the context) and C2 (one gold paragraph). C3 is left out because almost every answer is a refusal there.
- **Generator:** `gpt-4o-mini`, temperature 0, API seed 42, at most 64 output tokens.
- **No judge.** Only deterministic metrics are used, so judge noise does not mix with generator noise.

### What varies

- **Number of runs:** 10 runs per condition, then analyzed in groups of k = 1, 2, 3 and 5 runs.
- **Number of questions** (in the analysis only): random subsets of 25, 50, 100 and 150 questions.

### Metrics

- Exact match (EM), token-level F1 and abstention rate, over all questions, as in the first experiment.
- **A/A difference:** split the 10 runs into two disjoint groups of k runs, in every possible way, and take the absolute difference of the two group means. Its 95th percentile is the largest difference that noise alone produces in 95% of cases.
- **Question-sampling uncertainty:** half-width of the 95% bootstrap confidence interval of the mean over questions, for each number of questions.
- **Stability:** share of questions whose EM is not the same in all 10 runs.

### Cost

About $0.35 expected (3,000 generator calls). Phase 0 budget cap: $5, of which $1.23 was spent before this experiment.

### Versions

- Run date 2026-10-20. Python 3.12.14, `openai` 3.22.1, macOS on Apple silicon (API calls only).
- Generator `gpt-4o-mini-2024-07-18`, seed 42, temperature 0. Dataset revision and checksum as in the first experiment.

### Reproduce

From the repository root, after the setup steps of the first experiment (virtual environment, `.env`, `fetch.py`):

```bash
cd phase-0-evaluation/how-many-runs
../../.venv/bin/python experiment.py --runs 10 --out results/full   # about $0.35
../../.venv/bin/python analyze.py results/full
```

## Interpretation

Within one session, run-to-run noise is small, and the number of questions matters far more than the number of runs. The hypothesis that three runs are enough holds for runs made in the same session, but the same setup gave measurably different numbers on two different dates, which three runs on one day cannot reveal.

### Runs within one session

- With nothing changed, two single runs differ in EM by at most 1.3 points in 95% of cases (C1). With three runs per group the bound is 0.9 points, with five runs 0.7 points. Going from 1 to 3 runs reduces this noise, but in absolute terms both are about one point, so extra runs only matter when the differences being compared are of that size. The 37-point C1 to C2 gap of the first experiment would have been visible with a single run.
- Most answers do not change at all: across 10 runs, only 6 of 150 questions changed their EM. In 21 (C1) and 19 (C2) questions the answer text varied, mostly without changing the score. The noise comes from a few borderline questions.
- F1 and abstention behave like EM, and C2 like C1.

### Questions versus runs

- With 150 questions, the uncertainty that comes from which questions were sampled (95% CI half-width 0.080 for C1 EM) is about nine times the run noise (0.009 with three runs). More runs cannot reduce it; only more questions can.
- This applies to absolute scores ("C1 EM is 0.57"): how well the number generalizes to other questions. When two setups are compared on the same questions, much of the question-to-question variation affects both sides alike. How much of it remains in such a paired comparison was not measured, because an A/A test has no real difference.

### Why the noise shrinks slowly

The uncertainty of a mean is σ/√n, so it falls with the square root of the number of measurements, not in proportion to it. Six times as many questions (25 to 150) narrowed the interval about 2.4 times (√6 ≈ 2.45), and five runs instead of one halved the A/A difference (√5 ≈ 2.2). Each further gain costs more measurements than the previous one.

### Different dates

C1 and C2 here are the same setup as in the first experiment, three weeks apart. All three C1 abstention values from 2026-09-30 (0.153 to 0.160) lie above all ten values from 2026-10-20 (0.127 to 0.147), and C1 EM and F1 are slightly higher today. The shift (about 0.02) is several times the within-session standard deviation (about 0.007). Mean generator latency also changed (0.82 s to 0.67 s). The model ID and seed were the same, so the change most plausibly comes from the serving side, which OpenAI describes as best-effort reproducibility for seeded requests; this is not proven here. The harness does not record the `system_fingerprint` the API returns, which would show a backend change. There are only two dates, so a backend change cannot be told apart from ordinary day-to-day variation.

The practical consequence: the noise that matters when two setups are run on different days is larger than the within-session noise measured above. Variants should be run in the same session, ideally interleaved per question, and absolute numbers should carry their run date.

### Cost, latency and operations

Total spend was $0.35 (about $0.035 per run, no judge). No failed attempts and no truncated answers. Mean latency was 0.67 s per call in both conditions.

### Limits

One generator, one dataset (HotpotQA hard questions), two contexts, two dates. Only an A/A comparison was run; no pair of setups with a real small difference was tested. A/A differences are coarse because EM over 150 questions moves in steps of 1/150 ≈ 0.0067.

## Takeaway

For this generator, two or three runs per setup are enough to keep run noise around one point of EM; beyond that, adding questions narrows the uncertainty far more than adding runs. Compare setups in the same session, ideally interleaved, because results for the identical setup shifted by about two points between two dates. These numbers hold for `gpt-4o-mini` at temperature 0 on 150 HotpotQA questions; other models, higher temperatures or LLM judges may be noisier.

## Open

- Why did the same setup give different results on 2026-09-30 and 2026-10-20? Record the API's `system_fingerprint` in `shared/eval/llm.py` and repeat a short run on several dates.
- How much question-sampling noise remains when two setups are compared on the same questions? Needs a pair of setups with a real, small difference and a paired test.
- How noisy is an LLM judge across runs? The judge was left out here.
- Do higher temperatures or other models change the picture?
